# Publicación de Sokker++ en Chrome Web Store

> Informe de investigación de `gpt-6-luna` (Codex, esfuerzo high, búsqueda web), 2026-10-09. Verificar importes y campos en el Developer Dashboard al publicar.
> **Actualización 2026-10-09:** el propietario confirmó que Sokker permite usar los endpoints `/api`; `api.sokker.org` se quitó de `host_permissions` y el acceso quedó limitado a `https://sokker.org/*`. La política de privacidad y la ficha están en `PRIVACY.md` y `store/`.

**Estado: no listo para enviar.** La extensión ya tiene MV3, iconos y una descripción de manifiesto válida. Faltan elementos obligatorios de la ficha y la política de privacidad; además, las reglas de Sokker plantean un riesgo concreto para el método de acceso a datos. Revisé fuentes en vivo el **9 de octubre de 2026**; algunas páginas oficiales de requisitos llevan años sin actualizarse, así que conviene confirmar los campos en el Developer Dashboard al publicar.

## 1. Checklist obligatorio

- [ ] **Cuenta de desarrollador:** registrarse, pagar la tarifa única —la fuente oficial de Google aún indica **USD 5**; confirmar el importe al pagar—, mantener actualizado el correo de contacto y activar la verificación en dos pasos. La insignia de publisher verificado mediante un sitio web propio es opcional; no encontré en las fuentes consultadas una verificación universal de identidad exigida a todos los publicadores individuales. ([registro](https://developer.chrome.com/docs/webstore/register/), [anuncio oficial de la tarifa](https://blog.chromium.org/2020/03/new-developer-dashboard-and.html), [políticas y 2 pasos](https://developer.chrome.com/docs/webstore/program-policies/policies))
- [ ] **Ficha:** título, descripción detallada, categoría e idioma; el resumen y la descripción del manifiesto tienen límite de **132 caracteres**. Se requieren icono de tienda de 128×128, al menos una captura de **1280×800 o 640×400** (máximo 5) y un mosaico promocional de **440×280**. El mosaico marquee de 1400×560 es opcional. La documentación de ficha también enumera un video de YouTube; la guía de imágenes identifica como obligatorios icono, mosaico pequeño y captura, así que confirmar el video en el Dashboard. ([ficha](https://developer.chrome.com/docs/webstore/cws-dashboard-listing), [imágenes](https://developer.chrome.com/docs/webstore/images), [manifiesto](https://developer.chrome.com/docs/webstore/prepare))
- [ ] **Privacy practices:** declarar un propósito único —seguimiento del historial de habilidades y estimación de talento—, justificar cada host permission, indicar que no ejecuta código remoto y completar las declaraciones de datos y la certificación de Limited Use. ([campos de privacidad](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy))
- [ ] **Política de privacidad:** obligatoria si el producto maneja **cualquier dato de usuario**, aunque solo se guarde localmente. Debe explicar qué datos obtiene, cómo los usa y comparte, y estar enlazada en el campo del Dashboard. La ficha, las declaraciones de privacidad y el comportamiento deben coincidir. ([políticas oficiales](https://developer.chrome.com/docs/webstore/program-policies/policies))
- [ ] **Limited Use y consentimiento:** usar los datos solo para el propósito declarado; no venderlos ni usarlos para publicidad personalizada. La política también exige una declaración afirmativa de cumplimiento en un sitio del producto y revelar los datos y su uso antes de la instalación con consentimiento informado. ([Limited Use](https://developer.chrome.com/docs/webstore/program-policies/limited-use), [políticas oficiales](https://developer.chrome.com/docs/webstore/program-policies/policies))
- [ ] **MV3 y código:** la funcionalidad debe poder entenderse a partir del paquete. No ejecutar lógica remota ni código remoto —las consultas a una API para obtener datos no son por sí solas código remoto—. Se permite minificar; se prohíbe ofuscar u ocultar funcionalidad. ([requisitos MV3](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements), [legibilidad](https://developer.chrome.com/docs/webstore/program-policies/code-readability))
- [ ] **Marca:** no sugerir autorización, afiliación ni respaldo de Sokker; no infringir marcas o derechos ajenos. El nombre por sí solo no demuestra infracción, pero la ficha y los recursos deben dejar claro que es una herramienta independiente. ([propiedad intelectual e impersonation](https://developer.chrome.com/docs/webstore/program-policies/impersonation-and-intellectual-property))
- [ ] **Envío y revisión:** subir un ZIP cuyo directorio raíz contenga `manifest.json`, completar ficha y privacidad, y enviar a revisión. Google indica que la mayoría de las revisiones tardan unos días, aunque pueden tardar varias semanas; los permisos de host amplios y el código difícil de revisar pueden alargarlas. ([preparar y empaquetar](https://developer.chrome.com/docs/webstore/prepare), [proceso de revisión](https://developer.chrome.com/docs/webstore/review-process))

## 3. Riesgos de rechazo específicos

1. **Uso de la API del juego:** es el riesgo más concreto. Las reglas de Sokker mencionan XML como método aprobado, mientras el código usa endpoints `/api`; el permiso de Chrome no concede autorización bajo las reglas del juego.
2. **Privacidad y sync automático:** publicar sin política y declaraciones coherentes es un gap obligatorio. El sync en carga de página eleva el riesgo si el usuario no entiende qué datos se obtienen y cuándo.
3. **Marca “Sokker”:** no implica rechazo automático, pero la ficha no debe aparentar ser oficial ni infringir derechos. “No afiliada” ayuda a evitar confusión, aunque no sustituye autorización de marca si fuese necesaria.
4. **Hosts:** no son `<all_urls>`, pero la amplitud de rutas y `*://` puede motivar preguntas de revisión; explicar necesidad y reducir acceso sobrante.

## 4. Pasos siguientes, en orden

1. Confirmar con Sokker si `/api/current`, `/api/training` y `/api/player` están permitidos para esta extensión.
2. Publicar una política de privacidad con datos, finalidad, IndexedDB, solicitudes a Sokker, exportación local y ausencia de backend/analítica; incluir Limited Use.
3. Resolver la divulgación y el consentimiento del sync automático; completar Privacy practices con declaraciones que coincidan con el código y la política.
4. Preparar ficha en inglés o español: descripción, categoría, idioma, una captura válida y mosaico 440×280; añadir aviso de independencia.
5. Reducir/justificar host permissions y revisar el uso de HTTPS; crear ZIP desde el `dist/` actual.
6. Registrar la cuenta, pagar la tarifa vigente, activar 2 pasos y enviar a revisión.
