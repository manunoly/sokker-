Recovered into the existing TypeScript owners:

- Exact beta player routes for transfers/development, keeping host/protocol and safe-ID validation.
- Classic-table versus beta-card profile selection by actual DOM, including either markup under the other route format.
- Main team progress retains charts/history interactions and native colors, skips automatic comparison reads, and clears earlier highlights. This supersedes the 0.2.8 PR's coloring behavior.
- Storage disconnect diagnostics read `chrome.runtime.lastError` during the event and preserve it in the error, retaining fallback and mutation receipts.
- An explicit supported popup action retries a failed initialization; automatic rescans do not. Migration/readback failures continue to block all downstream work.

Junior routes, same-week updates, manual refresh, ownership/epoch guards, bounded concurrency, hover timing, native links and all other executable behavior match the published baseline.

## Limits and disposition

This is a source/package reconciliation, not an authenticated Sokker session or an MV3 installation/migration test on a real account. The browser harness does not certify Chrome service-worker lifecycle, persistent IndexedDB, real-page CSS or store acceptance. No real account data or credentials were accessed. The byte-identical executable comparison establishes that no shipped runtime change was dropped; it does not claim the published runtime is free of pre-existing bugs.

Update the existing PR only. Keep it open, leave main unchanged, and do not publish to the store.
